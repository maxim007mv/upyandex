# Система управления информационными рассылками

## Название проекта

**Система управления информационными рассылками**  
(вариант: пользователь, рассылка, сообщение, статус)

## Назначение

Консольная учебная программа для создания и учёта информационных рассылок.
На данном этапе реализован вход администратора и сценарий создания черновика
рассылки с расчётом условной стоимости отправки.

В дальнейшем проект будет развит до полноценного веб-приложения на **Django**
с базой данных, пользователями, API и остальными компонентами дисциплины.

## Целевая аудитория

- администраторы и операторы информационных рассылок;
- студенты, изучающие Python и веб-разработку на Django;
- преподаватели при проверке практических работ.

## Описание предметной области

Система позволяет готовить массовые информационные сообщения для получателей.
Администратор входит в систему, создаёт рассылку, указывает число получателей
и выбирает статус. Позже появятся хранение в БД, шаблоны писем, отправка
и отслеживание статуса каждого сообщения.

## Основные сущности

| Сущность   | Описание (на уровне предметной области)      |
|------------|-----------------------------------------------|
| Пользователь | Администратор / оператор системы            |
| Рассылка   | Кампания рассылки (название, статус)          |
| Сообщение  | Единица доставки одному получателю            |
| Статус     | Состояние рассылки или сообщения              |

*На этапе ПР1 сущности представлены простыми переменными (без классов и БД).*

## Основные функции (ПР1)

1. Вход в систему по email и паролю.
2. Создание черновика рассылки (название, число получателей).
3. Расчёт условной стоимости отправки.
4. Выбор статуса рассылки (черновик / готова / отменена).
5. Вывод итога сценария в консоль.

**Данные для входа (ПР1):**
- email: `lomakin2006@gmail.com`
- пароль: `123`

## Отладка (ПР1, пункт 9)

Отладка — это остановка программы на выбранной строке, пошаговое выполнение
и просмотр значений переменных. Для сдачи достаточно отладчика **pdb** в терминале.

### Запуск через pdb (рекомендуется)

```bash
python3 -m pdb main.py
```

Команды вводить **латиницей** (английская `c`, не русская «с»).

| Шаг | Что ввести | Зачем |
|-----|------------|--------|
| 1 | `b 30` | точка останова на строке 30 (проверка логина) |
| 2 | `c` | продолжить выполнение до точки останова |
| 3 | email / пароль (см. ниже) | обычный ввод программы, **не** команды pdb |
| 4 | `p email` | показать значение переменной `email` |
| 5 | `p password` | показать значение переменной `password` |
| 6 | `n` | выполнить одну следующую строку (пошагово) |
| 7 | `q` | выйти из отладчика |

**Email / пароль** (когда программа спросит `Email:` и `Пароль:`):

```text
lomakin2006@gmail.com
123
```

После этого снова появится приглашение `(Pdb)` — тогда уже вводите `p email`, `p password`, `n`, `q`.

**Важно:** команды pdb (`p email`, `n`, `c`) вводятся только когда слева написано `(Pdb)`.  
Когда программа спрашивает данные (`Email:`, `Пароль:`, название и т.д.) — вводите только ответы программы.

### Другие точки останова для теста

Можно поставить сразу несколько точек и пройти весь сценарий. Запуск:

```bash
python3 -m pdb main.py
```

#### Тест A — логин (строка 30)

```text
b 30
c
```

Ввод:
```text
lomakin2006@gmail.com
123
```

В `(Pdb)`:
```text
p email
p password
n
```

Что смотреть: `email` и `password` совпадают с админом → условие ошибки не срабатывает.

#### Тест B — число получателей (строка 51)

```text
b 51
c
```

Ввод по порядку:
```text
lomakin2006@gmail.com
123
Новости недели
10
```

В `(Pdb)`:
```text
p raw_count
p recipient_count
n
```

Что смотреть: `raw_count` — строка `'10'`, после `int(...)` переменная `recipient_count` — число `10` (преобразование типов).

#### Тест C — расчёт стоимости (строка 60)

```text
b 60
c
```

Ввод:
```text
lomakin2006@gmail.com
123
Новости недели
10
```

В `(Pdb)`:
```text
p recipient_count
p price_per_message
n
p total_cost
```

Что смотреть: `10 * 2.5` → `total_cost` должен быть `25.0`.  
Если ошибочно написать `+` вместо `*`, здесь будет `12.5` — так находят учебную ошибку.

#### Тест D — выбор статуса (строка 75)

```text
b 75
c
```

Ввод:
```text
lomakin2006@gmail.com
123
Новости недели
10
2
```

(последняя `2` — статус «ГОТОВА К ОТПРАВКЕ»)

В `(Pdb)`:
```text
p choice
n
p status
p can_send
```

Что смотреть: при `choice == '2'` → `status = 'ГОТОВА К ОТПРАВКЕ'`, `can_send = True`.

#### Все точки сразу (полный проход)

```text
b 30
b 51
b 60
b 75
c
```

Дальше вводите данные программы; на каждой остановке смотрите переменные (`p ...`), затем снова `c`, пока не дойдёте до конца. Выход: `q`.

| Строка | Переменные для просмотра | Смысл теста |
|--------|---------------------------|-------------|
| 30 | `email`, `password` | проверка входа |
| 51 | `raw_count`, `recipient_count` | `str` → `int` |
| 60 | `recipient_count`, `price_per_message`, `total_cost` | операции / расчёт |
| 75 | `choice`, `status`, `can_send` | ветвление по статусу |

### Запуск кнопкой Debug в Cursor (F5)

Кнопка Debug / F5 может **не работать** на macOS с **Python 3.14** (Homebrew): ошибка
`ImportError: ... pyexpat ... Symbol not found: _XML_SetAllocTrackerActivationThreshold`.
Это сбой отладчика Cursor (`debugpy`), а не ошибка в `main.py`.

**Что делать:**

1. Для ПР1 используйте `python3 -m pdb main.py` (см. выше) — этого достаточно.
2. Если нужна именно кнопка Cursor:
   - **Cmd+Shift+P** → `Python: Select Interpreter`
   - выберите Python **3.12** или **3.13** (не 3.14)
   - поставьте красную точку слева от строки 30
   - запустите **Debug Python File** / **F5**
3. Альтернатива починить Python 3.14 в системе (не обязательно для лабы):
   ```bash
   brew reinstall expat python@3.14
   ```
