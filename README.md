# Система управления информационными рассылками

## Название проекта

**Система управления информационными рассылками**  
(вариант: пользователь, рассылка, сообщение, статус)

## Назначение

Консольная учебная программа для создания и учёта информационных рассылок.
Проект развивается по этапам дисциплины:

* **ПР1** — процедурная версия в `main.py`: простые типы данных, операции,
  преобразование типов, ветвления, импорт модулей;
* **ПР2** — модульная структура, обработка коллекций (поиск, сортировка,
  вывод), хранение данных в JSON-файле, обработка исключений, аннотации
  типов, автотесты **pytest** и линтер **flake8**;
* **ПР3** — ООП-версия в `oop.py` и пакете `mailing/`: классы, наследование,
  полиморфизм, инкапсуляция, собственные исключения, декораторы
  (`@property`, `@classmethod`, `@staticmethod`).

Код покрыт **автотестами** (49 тестов: pytest и unittest) и проверяется
в GitHub Actions (pytest + flake8).

В дальнейшем проект будет развит до полноценного веб-приложения на **Django**
с базой данных, пользователями, API и остальными компонентами дисциплины.

## Целевая аудитория

- администраторы и операторы информационных рассылок;
- студенты, изучающие Python, ООП и веб-разработку на Django;
- преподаватели при проверке практических работ.

## Описание предметной области

Система позволяет готовить массовые информационные сообщения для получателей.
Администратор входит в систему, создаёт рассылку, указывает число получателей
и выбирает статус; рассылки сохраняются в JSON-файл. Позже появятся хранение
в базе данных, шаблоны писем, реальная отправка и отслеживание статуса
каждого сообщения.

## ООП-принципы в проекте

| Принцип | Где применён | Пример |
|---------|--------------|--------|
| **Инкапсуляция** | все сущности | поля `_title`, `_password_hash`, `_status` закрыты; доступ через `@property`, изменение — только методами `change_status()`, `mark_sent()` |
| **Абстракция** | `models.py`, `senders.py` | `User(ABC)` и `Sender(ABC)` с `@abstractmethod`: «пользователя вообще» и «отправителя вообще» создать нельзя |
| **Наследование** | `models.py`, `senders.py` | `Admin(User)`, `Operator(User)`, `ConsoleSender(Sender)` |
| **Полиморфизм** | `User.role`, `Sender.deliver` | `user.role` возвращает «Администратор» / «Оператор»; доставку можно реализовать любым наследником `Sender` |
| **Композиция** | `Mailing`, `MailingService` | рассылка «состоит из» сообщений `Message` и ссылается на автора `User`; сервис содержит хранилище, тариф и отправителя |
| **Внедрение зависимостей** | `MailingService`, `ConsoleUI` | сервисы и функции ввода-вывода передаются в конструктор, а не создаются внутри |
| **Магические методы** | `models.py`, `services.py` | `__str__`, `__repr__`, `__eq__`, `__hash__`, `__lt__`, `__len__`, `__iter__`, `__contains__` |
| **`@property` / `@classmethod` / `@staticmethod`** | весь код | `Mailing.title`, `Tariff.standard()`, `Tariff.format()`, `Status.from_menu_choice()`, `Mailing.validate_title()` |
| **Перечисления (Enum)** | `models.py` | `Status` (ЧЕРНОВИК / ГОТОВА К ОТПРАВКЕ / ОТМЕНЕНА / ОТПРАВЛЕНА), `MessageStatus` |
| **Собственные исключения** | `exceptions.py` | базовое `MailingError` → `ValidationError`, `AuthenticationError`, `StateError`, `StorageError` |
| **Сериализация** | `models.py`, `storage.py` | `to_dict()` / `from_dict()` превращают объекты в JSON и обратно; `JsonStorage` сохраняет и загружает рассылки |
| **Безопасность** | `models.py` | пароль хранится только в виде хеша SHA-256, метод `check_password()`; в JSON тоже попадает только хеш |

## Основные функции

1. Вход в систему по email и паролю (пароль проверяется по хешу).
2. Создание черновика рассылки (название, число получателей).
3. Расчёт условной стоимости отправки по тарифу (2.5 руб. за сообщение).
4. Выбор статуса рассылки (черновик / готова / отменена).
5. Имитация отправки: создаются объекты `Message`, отчёт выводит `ConsoleSender`.
6. Вывод итога сценария в консоль.
7. Сохранение рассылок в JSON-файл `data/mailings.json` и загрузка при старте.
8. Обработка коллекции рассылок: поиск по названию, сортировка по алфавиту
   и по дате, вывод списка (модуль `mailing/services.py`, класс
   `MailingRepository`).

Ограничение учебной версии: не более **10 000** получателей
(`Mailing.MAX_RECIPIENTS`) — защита от случайно введённых огромных чисел.

**Данные для входа:**
- email: `lomakin2006@gmail.com`
- пароль: `123`

## Запуск


с модулем `pyexpat` — используйте Python 3.13 (см. раздел «Отладка»).

## Проверка ошибок

| Сценарий | Ввод | Ожидаемый результат |
|----------|------|---------------------|
| Успех (черновик) | email, `123`, «Новости недели», `10`, `1` | статус ЧЕРНОВИК, отправка не выполняется |
| Успех (готова) | … , `2` | «Рассылка готова к отправке (имитация).» |
| Отмена | … , `3` | «Отправка сейчас не выполняется (статус: ОТМЕНЕНА).» |
| Неверный пароль | `wrong@mail.com`, любой | «Ошибка: неверный email или пароль.», код выхода 1 |
| Пустое название | пустая строка | «Ошибка: название не может быть пустым.», код 1 |
| Не число | `abc` | «Ошибка: нужно ввести целое число.», код 1 |
| Ноль | `0` | «Ошибка: число получателей должно быть больше нуля.», код 1 |
| Слишком много | `10001` | «Ошибка: число получателей не должно превышать 10000.», код 1 |
| Неизвестный пункт | `9` | предупреждение и статус ЧЕРНОВИК |
| Повреждённый файл данных | испорченный `data/mailings.json` | «Ошибка: … файл данных …», код 1 (программа не падает) |

## Автотесты

Проект покрыт автотестами (**pytest**, 49 тестов). Часть тестов написана
в стиле `unittest`, часть — в стиле pytest; pytest запускает и те, и другие.
Тесты проверяют ООП-поведение классов, сервисы, JSON-хранилище и все
сценарии интерфейса (консольный ввод-вывод подменяется функциями из теста —
это возможно благодаря внедрению зависимостей в `ConsoleUI`).

Установка зависимостей разработки и запуск из корня проекта:

```bash
pip install -r requirements-dev.txt   # pytest, flake8
python -m pytest -v
```

Ожидаемый результат: `49 passed`. Можно запустить и через unittest
(42 теста — без pytest-тестов хранилища):

```bash
python -m unittest discover -s tests -t . -v
```

| Файл | Что проверяет |
|------|----------------|
| `tests/test_models.py` | абстрактность `User`, полиморфизм ролей, хеш пароля, статусы, валидацию `Mailing`, отправку, `__len__` / `__iter__` / `__eq__` / `__lt__` |
| `tests/test_services.py` | `Tariff` (цена, расчёт, формат), `AuthService` (вход, ошибки, дубликаты), `MailingRepository` (поиск, сортировка, состав), `MailingService` |
| `tests/test_storage.py` | JSON-хранилище (pytest): сохранение и загрузка, восстановление статусов и сообщений, ошибки файла, автосохранение из сервиса |
| `tests/test_ui.py` | сценарии `ConsoleUI`: успех, черновик, неверный пароль, пустое название, не число, ноль, превышение лимита, неизвестный пункт меню |

Дополнительно при каждом `push` и `pull request` тесты и линтер автоматически
запускаются на GitHub Actions (`.github/workflows/tests.yml`) на Python 3.10
и 3.13 — результат виден на вкладке **Actions** репозитория.

## Отладка (pdb)

Отладка — это остановка программы на выбранной строке, пошаговое выполнение
и просмотр значений переменных. Для сдачи достаточно отладчика **pdb** в терминале.

> Номера строк указаны для текущей версии файлов. Если код менялся,
> ориентируйтесь на имена методов (например, `_login`) — их видно в листинге.

### Запуск через pdb (рекомендуется)

```bash
python3 -m pdb oop.py
```

Команды вводить **латиницей** (английская `c`, не русская «с»).

| Шаг | Что ввести | Зачем |
|-----|------------|--------|
| 1 | `b mailing/ui.py:73` | точка останова на проверке входа |
| 2 | `c` | продолжить выполнение до точки останова |
| 3 | email / пароль (см. ниже) | обычный ввод программы, **не** команды pdb |
| 4 | `p email` | показать значение переменной `email` |
| 5 | `p password` | показать значение переменной `password` |
| 6 | `n` | выполнить одну следующую строку (пошагово) |
| 7 | `q` | выйти из отладчика |

**Email / пароль** (когда программа спросит `Email:` и `Пароль:`):

```text
lomakin2006@gmail.com
123
```

После этого снова появится приглашение `(Pdb)` — тогда уже вводите `p email`, `p password`, `n`, `q`.

**Важно:** команды pdb (`p email`, `n`, `c`) вводятся только когда слева написано `(Pdb)`.  
Когда программа спрашивает данные (`Email:`, `Пароль:`, название и т.д.) — вводите только ответы программы.

Полезно: `s` (step) — войти внутрь вызываемого метода, например из `ConsoleUI._login`
в `AuthService.login`, чтобы увидеть проверку пароля по хешу.

### Запуск кнопкой Debug в Cursor (F5)

Кнопка Debug / F5 может **не работать** на macOS с **Python 3.14** (Homebrew): ошибка
`ImportError: ... pyexpat ... Symbol not found: _XML_SetAllocTrackerActivationThreshold`.
Это сбой отладчика Cursor (`debugpy`), а не ошибка в коде.

**Что делать:**

1. Для лабораторной используйте `python3 -m pdb oop.py` (см. выше) — этого достаточно.
2. Если нужна именно кнопка Cursor:
   - **Cmd+Shift+P** → `Python: Select Interpreter`
   - выберите Python **3.12** или **3.13** (не 3.14)
   - поставьте красную точку слева от нужной строки (например, `mailing/ui.py:73`)
   - запустите **Debug Python File** / **F5**
3. Альтернатива починить Python 3.14 в системе (не обязательно для лабы):
   ```bash
   brew reinstall expat python@3.14
   ```
